# 报告结构与判断依据

根据任务深度调整篇幅，保留以下决策信息：

1. **结论与范围**：关键词、地区、设备、采集时间、覆盖/失败情况、最值得验证的切口和结论限制。
2. **检索地图**：原词、扩展词、对应用户任务、结果数；API 发现与品牌补充单独标记。
3. **品类地图**：官方分类、人工细分赛道、用户任务、代表应用；两种分类不要混写。
4. **竞品清单**：ID、应用链接、开发者、直接/相邻竞品、评分/评分数、下载价、版本日期、入选原因；记录代表性排除项。
5. **产品与商业化矩阵**：生成方式、编辑控制、导出/下游任务、收费、限制及来源；支持状态明确，未提及不等于没有。
6. **评论证据**：采集口径、样本数、日期范围、正负价值、可定位评论 ID；区分单条反馈与跨应用重复现象。
7. **机会优先级**：1–3 个方向的证据、反证、人群、最小产品范围、获客假设、依赖成本、实验和信心。
8. **下一步与证据索引**：下一周能做的验证、尚缺的关键数据、来源及原始文件链接。

使用定性高/中/低即可。若用户要求数值评分，公开维度、权重和赋分依据，将“方向吸引力”与“证据信心”分开，不制造虚假精确性。竞争应用多说明有供给；评分多说明有累计评分行为；二者都不能单独证明细分需求或竞争不可进入。

评论分析：先读取真实内容，再归类。每个主题列应用数与命中样本数、代表评论 ID、可能的版本/时效原因；一条可多标签，主题数量不能加总成用户数。不要把预设关键词命中直接称为已验证痛点。保留用户称赞的核心价值，避免只看差评。

机会可用下面的决策卡：

| 项目 | 内容 |
|---|---|
| 用户与任务 | 谁在何种情境下要完成什么 |
| 当前替代方案 | 包括现有竞品、人工流程或不做 |
| 证据 | 观察事实与来源 |
| 机会假设 | 推断及尚缺证据 |
| 反证 | 竞品已覆盖、用户不在意、成本过高等 |
| 最小交付 | 只包含验证核心任务所需能力 |
| 验证与门槛 | 预先提出可观察的成功/停止条件；阈值标注为实验假设 |
| 信心 | 基于证据质量、样本覆盖与矛盾情况 |

涉及 AI 音乐时，区分生成、翻唱/换声、分轨/编辑、视频配乐、个性化收听等任务；这些只是起始假设，应由实际结果调整。商用许可、声音授权和输出权利仅转述当前官方条款及适用套餐；宣称 royalty-free 不等于对所有使用场景提供法律保证。
